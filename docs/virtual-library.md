# 虚拟媒体库

把在线内容做成飞牛影视首页里的媒体库：官方媒体库列表里多出 4 个榜单库与 4 个海量分类库，
点开就是海报墙，点进条目即可走既有的详情 / 选集 / 多线路 / 续播 / 代理播放链。

> 虚拟库只在本扩展内伪造条目，**不写官方数据库、不改官方二进制**。关闭总开关或停用扩展后，
> 媒体库首页立即恢复官方原样。

## 两层结构

| 层 | 数据来源 | 播放方式 |
|---|---|---|
| 榜单四库（🎬热门电影 / 📺热门剧集 / 🌸动漫新番 / 🎤热门综艺） | 豆瓣公开榜单（60s 免 key 转发 + 豆瓣 tag 推荐），只取片名 / 海报 / 评分 / 年份 / 简介 | 点进详情时才按片名聚合搜索已启用资源站，命中后把可播放 brief 挂到该榜单 guid |
| 海量四库（🎞海量电影 / 📺海量剧集 / 🌸海量动漫 / 🎤海量综艺） | 各资源站 Apple CMS 分类表 + `ac=detail&t=<子类>&pg=N` 深翻 | 条目本身带播放地址，点开即播，无需再搜索 |

榜单 guid = `md5("fnmedia-chart:<cat>:<douban_id>")`，媒体库 guid =
`md5("fnmedia-vlib:chart:<cat>")` / `md5("fnmedia-vlib:catalog:<cat>")`，
与官方库、在线搜索结果（`md5("on_<provider>_<vodid>")`）完全隔离。

## 接管的接口

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/v/api/v1/mediadb/list` | 透传官方后，剥离重复虚拟库并把 8 个库插到最前；官方失败时以虚拟库兜底 |
| GET | `/v/api/v1/mdb/{guid}` | 虚拟库返回库详情（名称、分类、海报墙）；其他 guid 原样透传 |
| GET | `/v/api/v1/mediadb/sum` | 在官方统计里追加每个虚拟库的条目数与 `total` |
| POST | `/v/api/v1/item/list` | `ancestor_guid`/`parent_guid` 命中虚拟库时按 `page` / `page_size` / `offset` 返回海报墙 |

榜单条目还接入了：`item/{guid}`（懒绑定后返回标准详情）、`play/info`、`stream/list`、
`stream`、`play/play`、`media/range`。绑定前这些接口会先做一次搜源（单飞 + 3 分钟失败冷却），
成功后 media/video/episode guid 全部注册进 `TitleStore`，后续链路与普通在线条目完全一致。

## 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `vlib_enabled` | `true` | 总开关 |
| `vlib_charts` | `true` | 榜单四库 |
| `vlib_catalog` | `true` | 海量四库 |
| `vlib_refresh_hours` | `6` | 后台刷新间隔（1–24 小时） |

管理页「虚拟媒体库」可查看榜单数据源成功数、各库条数、已绑定条目数、分类路由来源，
并支持「立即刷新」与「清空虚拟库缓存」。

## 磁盘状态

| 文件 | 内容 | 可再生 |
|---|---|---|
| `state/charts.json` | 榜单元数据（片名/海报/评分），最多 160 条/库 | 是 |
| `state/catalog.json` | 分类路由（源、子类 id、页数、总数、封面样本） | 是 |
| `state/chart_bindings.json` | 榜单 guid → 已搜源命中的可播放 brief，TTL 6 小时，上限 400 条 | 是（重新搜源） |

三者都是缓存，删除或「清空虚拟库缓存」不会影响配置与官方数据。

## 刷新与容错

- 后台任务启动 5 秒后检查一次，之后每 10 分钟检查是否过期；媒体库列表只读缓存
  （stale-while-revalidate），刷新永远不阻塞页面。
- 榜单：任一配方（周榜 / 某个 tag）失败不影响其他；整体失败或结果为空时**保留旧缓存**，
  没有旧缓存时榜单库不注入（不会出现空库）。
- 海量库：分类表读取失败时保留旧路由；某页失败自动收敛总数，让前端自然停止滚动。
- 榜单绑定失败（源站没有该片）返回 `can_play=0` 与「暂无在线片源」，不误导用户。

## 已知限制

- 豆瓣榜单接口可能被网络环境拦截；被拦时榜单四库不出现，海量四库与搜索不受影响。
- 榜单条目按「片名规范化 + 年份」匹配资源站，极少数同名不同作品可能匹配到错误条目；
  海量库条目直接来自资源站，不受此影响。
- 海量库需要资源站支持 `ac=list` 分类表；不支持时该库不出现。
- 虚拟库条目不参与官方刮削，也不写入官方「继续观看」数据库；进度仍由扩展自己的
  `state/config.json → playstate` 维护（见 [playback.md](playback.md)）。

## 验证步骤

1. 管理页「虚拟媒体库」→「立即刷新榜单与分类」，确认榜单成功数 > 0、海量库有总数。
2. 打开飞牛影视 → 媒体库，应看到「🎬热门电影」等虚拟库；点开有海报墙、可翻页。
3. 点一个榜单条目 → 详情页出现线路与选集；播放能起播（首次进入需几秒搜源）。
4. 关掉总开关 → 重新进入媒体库，虚拟库消失、官方库不变。
