# 播放链路

- 起播默认 3s 并发优选最快线路（`auto_best_source` 可关），失败自动换线。
- 播放清单失败会自动在候选线路间换线；播放中途失败仍需手动切换线路，不做后台自愈。
- 内网自建源默认可用：m3u8 / mp4 直链可指向 `127.0.0.1`、`localhost`、`192.168.x.x`、`10.x.x.x` 等局域网或回环地址；链路本地与云元数据地址始终拦截。可在「设置 → 内网自建源」关闭 `allow_intranet`，恢复仅公网目标。

## 播放状态（收藏 / 已看 / 续播）

在线条目是虚拟 item，官方数据库中没有对应记录，因此官方的收藏、已看与播放历史接口对它们都会返回业务错误。扩展自行拦截并维护这些状态（不写官方数据库）：

- 拦截 `PUT/DELETE /v/api/v1/item/favorite`、`POST/DELETE /v/api/v1/item/watched`、`POST/DELETE /v/api/v1/favorite/list`、`POST /v/api/v1/play/record`、`GET /v/api/v1/play/list`、`POST /v/api/v1/play/info`，并在详情与搜索卡片回填 `is_favorite / is_watched / watched_ts / ts / duration`。
- 续播：官方 Web/App 拿 `play/info` 响应里的 **`item.watched_ts`**（秒）作为起播位置，外层 `ts` 不会被读，因此两处同步回填；`play/play` 请求里的 `startTimestamp` 会带进播放地址，HLS 点播清单再注入 `#EXT-X-START`，让不自行 seek 的原生播放器也能接着播。起播点超过片长 95% 视为“已看完重看”，从头开始。
- `watched_ts` 只表示播放进度（秒）；“标记已看的时间”放在 `watched_at`，不能混用——客户端会把 unix 时间戳当成播放位置跳到片尾。
- 剧集进度按“最后观看的那一集”记录：换集时不会用旧集位置取 max，选集列表只给该集回填进度条；`play/info` 传剧 guid 时会解析到最后观看的那一集。
- 收藏、已看、收藏夹、首页「继续观看」均可用；看完 95% 自动移出继续观看并标记已看。
- 更多菜单里「手动匹配影片 / 刷新元数据 / 编辑元数据 / 删除」对虚拟条目语义上不适用，相关写请求吸收为 no-op，不再向官方报错。
- 状态统一存于 `state/config.json` 的 `playstate` 键：收藏上限 500、历史上限 100，进度 10 秒节流写盘，服务停止时强制落盘。
- 已知限制：标题库为纯内存态，服务重启后收藏/历史卡片需要重新搜索同名条目才会重新可播；状态本身不会丢失。多账号共用一份状态（未做用户隔离）。**账号权限（`docs/source-acl.md`）只控制「能看到哪些库 / 源」，不隔离收藏与进度**——A 账号的续播进度在 B 账号看到同一部片时仍会生效，这是阶段 3 的收尾项。

## 详情页图片（海报 / 背景）

详情响应的 `poster`、`backdrops`、`posters`、`logos` 必须全部落在本站 `/online/<token>.jpg` 代理上，不能把外链直接交给客户端：

- 豆瓣、TMDB、优酷等图床都有 Referer 防盗链，客户端直连只会拿到 403，表现为详情页顶部背景一片黑、而下方海报正常；
- 借库（`borrow.enrich_detail`）会把官方库里的 `backdrops` / `posters` 覆盖进来，豆瓣补图（`douban.enrich_poster`）会塞入豆瓣原图 URL，两者都是外链；
- `fake.adopt_images()` 统一处理：外链转代理；既不是外链、也不以 `/` 开头的值（官方库里的图片 ID / hash）退回 CMS 海报；`poster` 为空时用第一张剧照反哺。

## 手机 App 原画直链兜底

飞牛影视手机 App 播放订阅源条目时，拿不到官方转码会话授权，会回退用条目 GUID 请求 `GET /v/api/v1/media/range/{hash}` 读原文件，官方必然返回 403「文件权限不足」。扩展接管该接口：

- hash 命中订阅源映射（fake media/episode GUID）时改由本模块供数：mp4 直链做 Range 代理（支持拖动进度），HLS 源 302 重定向到本模块 m3u8 播放链路（播放器跟随重定向播放）
- 官方真实文件的 hash 一律照旧透传，官方条目播放不受影响
- 线路选择沿用首选线路，被熔断线路自动避开；命中接管会写运行日志（`media/range takeover`）

## 广告切片过滤

按播放清单里的文本特征跳过广告分片，默认关闭，在管理页「广告过滤」开启。

- 三种判据可组合：显式广告标记（`#EXT-X-CUE-OUT/IN`、带广告标识的 `#EXT-X-DATERANGE`）、分片地址关键字（最多 32 个，不区分大小写）、片头跳过秒数（0–120）。
- 分段广告识别（`adfilter_breaks`，默认开启，主流 CMS 播放器做法）：按 `#EXT-X-DISCONTINUITY` 把清单切组，仅当某组同时满足「3–15 片、3–120 秒、不足最长组 5%、整份清单 2–10 组」才判为广告段；单组或分组过密的清单不处理。
- 强证据识别（`adfilter_strong`，默认开启，独立开关）：重复的分片 URL、小于 0.5 秒的非视频追踪分片、长清单中出现不超过 2 次的少数派域名。三类都是无条件自动推断、误判风险同源，与分段识别分开控制；某源若会循环复用正片分片，可单独关掉。
- 发生删除时清理保留段里残留的 CUE / DATERANGE 标签，以及广告段出口处孤立的 `#EXT-X-DISCONTINUITY`（前一分片已被删除时才清理，正片内部合法的编码切换标记保留），避免播放器在广告插入点重新初始化解码器。清理数量记入日志 `disc=` 与诊断页。
- 只读取 m3u8 文本，不下载分片内容、不增加起播等待；规则改动即时生效，无需清理缓存。
- 加密清单保留每个分片的原始序号，避免 AES-128 解密错位；过滤后同步修正展示时长与「看完 95% 标记已看」的判定。
- 命中情况写入运行日志（`adfilter: removed N segments ...`），可在「日志诊断」页查看，便于发现误判。
- 仅作用于订阅源的 HLS 媒体清单，官方本地影片完全不受影响；误判时关掉开关即原样恢复。
- 三重防误删：仅靠「片头跳过」命中、且被删分片与保留分片同域名同目录时，视为疑似正片并保留（`adfilter_head_guard`，默认开启）；片头跳过只作用于带 `#EXT-X-ENDLIST` 的点播清单；一次删除超过半数时长或 40 片时整次过滤回退为原清单。
- 日志新增 `cut=`（被删总秒数）、`total=`（原清单总时长）、`guard=`（保护原因）与 `guarded=`（被保护片数），管理页「广告过滤 → 最近清单诊断」可查看每个被删分片的地址、时长、命中原因，以及清单改写前后片段。诊断记录只在内存保留最近 5 条，不落盘。
- 已知限制：不做内容探测、不自动学习规则；源站若把广告直接混在视频内容里而不是独立分片，本功能无效。跨源差异需自行配置关键字，不建议用「分片时长短」判广告，正片常见 6 秒切片。若广告分片与正片同域名同目录，保护规则会把它一并保留，此时需改用关键字或关闭保护。

使用者需自行确认该功能的合法性。
